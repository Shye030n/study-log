## 4) 개념
### 4-1 함수는 자판기
          인자(돈, 버튼)
               ↓
   ┌───────────────────────┐
   │  function add(a, b) { │ ← 매개변수: 자판기 투입구
   │    return a + b;      │ ← 본문: 내부 처리
   │  }                    │
   └───────────────────────┘
               ↓
          return 값(음료)

    - 자바의 메서드와 같은 역할
    - JS는 클래스 밖에서도 함수를 독립적으로 만들 수 있다.

### 4-2 함수를 호출할 때의 동작 원리
```
const r = add(2, 3);
```
1. add라는 이름의 함수를 찾는다.
2. 인자 2, 3을 매개변수 a, b에 넣는다. 
3. 본문 실행 : a + b 의 결과 5
4. return 5 한 값을 함수를 호출한 자리에 넣는다.  add(2, 3) = 5 
5. const r = 5

### 4-3 자바 메서드와 다른 점 _ Javascript 함수
- 반환 타입 선언 : X <-> 필수 (int, void)
- 매개변수 타입 : X <-> 필수
- 인자 개수가 안맞으면 : 부족하면 undefined, 넘치면 무시 <-> 컴파일 에러
- 오버로딩 : X. 같은 이름으로 또 만들면, 덮어써버림 <-> 가능
- return 없음 : undefined로 반환 <-> void
- 함수를 변수에 담기 : 자유롭게 가능 <-> 람다로 제한적 ----------!!!! TODO : 람다
=> "인자 개수가 달라도 에러가 안난다" 가 JS 버그의 흔한 원인. 
    따라서 기본값 매개변수 function f(a, b = 1)로 빠진 값을 대비한다.
    - 자바의 람다: 자바도 함수를 변수에 담을 수는 있지만, 반드시 함수형 인터페이스 타입이 필요. 
    ```
    Function<Integer, Integer> doubleIt = x -> x * 2;   //타입을 정해야 함
    doubleIt.apply(3);
    ```
    자바는 doubleIt.apply(3)으로 호출하고, 
    JS는 doubleIt(3)으로 바로 호출. const doubleIt = x => x * 2; 처럼 타입 없이 담음. 
    그래서 자바는 제한적, 자바스크립트는 자유롭게. 이 정도 차이만 우선 알아두도록.

### 4.4 함수를 만드는 세 가지 방법
    
    ```
    // 1. 함수 선언문
    function add(a, b) { return a + b; }

    // 2. 함수 표현식 : 이름 없는 함수를 만들어 새로운 변수에 담음
    const add = function(a, b) { return a + b;}

    // 3. 화살표 함수
    const add = (a, b) => a + b;            //코드가 한 줄이면 { return ; }생략 가능
    const add = (a, b) => { return a + b; } // 여러 줄이면 { return ; } 필요
    ```
- 변수에 담기 = 2, 3
- WebSquare 패턴) 객체의 속성에 담기. scwin.btn_onclick = function() {...}
- 다른 함수에 인자로 넘기기 (Day5 콜백)

### 4.5 fn vs fn() _ 가장 중요한 구분
```
add         // 함수 그 자체   typeof = "function" (!typeof의 결과는 항상 문자열이다)
add(2, 3)   // 함수를 실행한 결과   typeof = "number"
```
- 실행 결과(숫자, 문자열)에 다시 ()를 붙이면 xxx is not a function 에러 발생

### 4-6 함수 호이스팅 _ Day1과 연결
JS의 코드 실행 전 준비 단계에서 엔진이 함수를 등록하는 방식이 함수마다 다르다.

[1단계 : 준비]
- 함수 선언문 : 준비 단계에서 함수 본체까지 통째로 준비해서, 함수 선언식 위에서 호출 가능 (여기만, 변수개념에서 추가로 외울 부분)

- const 함수명 = function(){} : 함수 등록만 함. TDZ. 초기화 전에 호출하면 "Cannot access xxx before initialization"으로 접근 불가. (변수랑 똑같)
- let 은? const와 동일하고, 함수를 담은 변수는 재할당할 일이 거의 없어서 실무에서는 함수에 거진 const만 사용.
- var 함수명 = function(){} : 등록 + undefined로 초기화 (변수랑 똑같)

### 4-7 함수 스코프
: 자바와 동일하게, 함수 안 지역변수를 메서드 밖에서 사용할 수 없는 것처럼
자바스크립트도, 함수 안에서 선언한 지역변수를 함수 밖에서 사용할 수 없는 것과 똑같은 개념.

## 5) 실무 연결 포인트
- WebSquare의 이벤트 함수는 대부분 이런 모양이다.
    ```
    scwin.btn_search_onclick = function(e) {...};
    ```
    => 함수표현식을 scwin 객체 속성에 담는다 (Day2 + Day3)
- 이벤트에는 함수를 "참조"로 연결한다. 컴포넌트 속성에 scwin.btn_search_onclick처럼 괄호 없이 연결하고, 클릭이 일어날 때 WebSquare가 대신 ()를 붙여 실행해준다. fn과 fn()의 개념이 확실치 못하면 "화면 열자마자 실행되버림" 또는 is not a function 버그 발생
- 공통 함수
    : 대부분의 프로젝트에는 금액포맷, 날짜변환, 필수값체크 등 공통 유틸 함수 파일이 있다. 신입이 처음 하는 일 중 하나가 이걸 읽고 호출하는 것이기에, 
    => 매개변수와 return을 보는 눈이 신입에게 중요하다.
- 인자 누락 버그
    : 공통 함수에 인자를 하나 빠뜨려도 에러가 안나고, undefined가 들어가도 엉뚱한 결과가 나온다. 
    즉, 에러는 없는데 값이 이상하다 => "인자 개수"부터 의심하기!
- 화살표 함수 주의
    : 화살표 함수는 this 동작이 일반 함수와 다름.(Day3) 레거시 WebSquare 코드는 대부분 function() 형태라 이벤트 함수는 기존 코드 스타일을 따르는게 안전하다.
- is not a function 읽기
    : 이 에러가 나면 "함수가 아닌 것에 ()를 붙였다"는 뜻. 
    => "이름오타, 호이스팅순서, fn()결과값 재호출" 부터 의심하기!
